# 交互五线谱缩放控制设计

日期：2026-08-15

> **实施状态（2026-08-15）：** 方案 A 已落地；后续性能优化将快速连续缩放合并到最终档位后再做一次 OSMD 重排，百分比按钮仍立即反映用户的目标档位。

## 1. 背景与问题

当前练习页按 OSMD 默认比例排版。iPhone 14 Pro 纵屏下一屏通常只能看到约三行钢琴双谱表，浏览长曲目时需要频繁滚动。用户希望能把谱面缩小到参考图中的页面密度，并在底部直接放大或缩小，同时保留现有的小节点击跳转、播放高亮和自动跟随。

## 2. 目标

- 练习页默认以 70% 显示谱面，在常见 iPhone 纵屏中优先达到约 4–5 行双谱表可见。
- 提供底部常驻的“缩小 / 当前百分比 / 放大”控制。
- 缩放范围为 50%–140%，每次调整 10%。到达边界时禁用对应按钮。
- 缩放后重新排版谱面，并重新计算小节点击矩形与高亮位置。
- 当前小节在缩放后仍保持高亮，并尽量保持在可视区域。
- 切换 MIDI 声部、重新生成 MusicXML 或播放时保持当前页面的缩放比例；打开新的练习页时恢复 70%。

## 3. 不在本次范围

- 不持久化为跨页面或全局设置。
- 不增加横向分页、打印排版或出版级页边距控制。
- 不用双指手势替代底部按钮；现有滚动和多指手势过滤继续保持。
- 不改变 MIDI 播放速度、音高、声部选择或 MusicXML 内容。

## 4. 方案比较

### 方案 A：OSMD 原生缩放并重新排版（采用）

通过本地 renderer bridge 设置 OSMD 的 `Zoom`，重新渲染后重建 measure overlay，并把新 layout 发回 Flutter。

优点：谱面、滚动高度、小节矩形和点击坐标使用同一套真实布局；字体与符号保持矢量清晰；能继续复用现有高亮和自动跟随协议。

代价：每次点击缩放会触发一次 OSMD 重排，需要显示短暂但非阻断的重排状态，并用 generation 防止快速连点的旧结果覆盖新结果。

### 方案 B：CSS transform 整体缩放（不采用）

优点是实现简单，但视觉尺寸、DOM 滚动高度和 measure overlay 坐标容易分离，会重现“高亮框与真实小节错位”的问题。

### 方案 C：WKWebView 页面缩放或仅依赖双指手势（不采用）

实现依赖平台浏览器行为，按钮难以获得稳定百分比，且会与滚动、小节点击和多指防误触逻辑冲突，不适合作为产品主控制。

## 5. 界面设计

缩放控制放在谱面视口底部、固定播放栏上沿，采用紧凑浮动胶囊，不扩大播放栏，也不挤占“速度、上一小节、播放、下一小节、AB”五个现有位置。

- 左侧为减号按钮，语义标签“缩小乐谱”。
- 中间显示整数百分比，例如“70%”。
- 右侧为加号按钮，语义标签“放大乐谱”。
- 胶囊使用现有深紫棕色与浅金色体系，和固定播放栏一致；背景具有足够不透明度，避免音符穿透影响识别。
- 单个按钮触控区域至少 44×44 pt。
- 控件只在存在可显示 MusicXML 时出现；生成中、错误态和纯 MIDI 空态不显示。
- 50% 时减号禁用，140% 时加号禁用；禁用态仍保留位置，避免布局跳动。

## 6. 状态与数据流

`ScorePracticePage` 持有页面级 `scoreZoom`，初始值 0.7。它把 zoom 传给 `InteractiveScoreView`，并把增减回调传给缩放胶囊。

`InteractiveScoreView` 把初始 zoom 与 MusicXML 一起交给 renderer；后续 zoom 变化只调用本地 `setZoom`，不重新编码或重新加载 MusicXML。renderer 保存当前 zoom，在 OSMD ready 前收到的 zoom 也会用于首次 render，避免先 100% 后 70% 的闪烁。

renderer 的缩放流程：

1. 校验并限制 zoom。
2. 增加缩放 generation，只接受最新一次请求。
3. 设置 OSMD `Zoom` 并重新渲染。
4. 以新 SVG 几何重建所有小节 overlay。
5. 恢复当前小节高亮，必要时滚动到可视区。
6. 发送新的完整 layout；Flutter coordinator 继续使用该 layout 做点击命中。

声部切换会替换 MusicXML，但不重建页面级 `scoreZoom`，因此缩放比例保持。离开并重新打开练习页时 State 销毁，恢复 70%。

## 7. 并发与错误处理

- 快速连续点击缩放时采用 last-request-wins；旧重排不得覆盖新比例的 DOM、layout 或错误态。
- renderer 未 ready 时允许先更新期望 zoom；首次 render 直接使用最新值。
- 当前缩放失败时保留上一次成功谱面和比例，向 Flutter 发送可读错误；不清空谱面、不影响播放。
- surface 替换或页面销毁后，旧缩放回调必须失效。

## 8. 测试与验收

### 自动测试

- 默认显示 70%，减号与加号分别按 10% 调整。
- 50%/140% 边界正确禁用，百分比不会越界。
- 只有存在 MusicXML 时才显示缩放胶囊。
- 切换声部或替换 MusicXML 后保持当前 zoom；新建页面恢复 70%。
- WebView 首次加载直接携带当前 zoom，后续缩放不重复发送 MusicXML。
- JS bridge 使用 OSMD `Zoom` 重新 render，重建 layout 并恢复高亮。
- 快速缩放只发布最后一次 layout，旧 surface 消息被忽略。
- 真实 WKWebView integration 在 70% 与至少另一个比例下验证：layout 非空、矩形落在 SVG 范围、非首小节点击仍命中。

### 视觉验收

- 在与用户截图相同的 iPhone 纵屏尺寸、K.478 默认钢琴双谱表状态下截图。
- 把参考图和实现截图放在同一比较输入中确认：70% 时一屏约 4–5 行，谱面未裁切，底部缩放胶囊不遮挡当前高亮或固定播放栏。
- 分别缩小和放大一次，确认符号仍清晰、页面高度同步变化、小节高亮完整覆盖真实谱表。

## 9. 验收标准

用户打开练习页时能立即看到比当前更紧凑的谱面；点击底部减号或加号后百分比和谱面密度同步变化。无论缩放到何种允许比例，点击可见小节都能跳转到对应播放小节，高亮与自动跟随不发生坐标错位。
