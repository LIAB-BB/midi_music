# 测试分发说明

本文说明当前阶段如何把 App 发给别人测试。它面向第一批小范围测试，不等同于正式发布流程。

## 当前推荐方式

### Android

第一批测试优先使用 debug APK：

```bash
flutter build apk --debug
```

构建成功后的文件通常在：

```text
build/app/outputs/flutter-apk/app-debug.apk
```

如果构建机提示：

```text
[!] No Android SDK found. Try setting the ANDROID_HOME environment variable.
```

说明当前机器没有可用 Android SDK，需要先安装 Android Studio / Android SDK，或在已配置 Android SDK 的机器上执行同一条命令。

发给测试者前，建议同时发送：

- `docs/真机测试清单.md`
- 当前分支名：`codex/ui-redesign-handoff`
- 当前提交 SHA
- 已知限制：debug 包、非正式签名、音色仍为 SoundFont MIDI

### iOS

当前不建议直接给普通测试者发 iOS 包，因为还缺：

- Apple Developer Team 签名配置
- Bundle ID 确认
- TestFlight 分发配置
- 隐私说明文案最终确认

iOS 现阶段适合开发者本机调试：

```bash
flutter build ios --debug --no-codesign
```

真正给外部测试者用，应走 TestFlight。

## 给测试者的话术

```text
这是 MIDI 伴奏 App 的早期测试包。

请先用首页的“示例曲目”测试播放，不需要自己准备 MIDI 文件。
如果没有声音或跟随模式无法使用，请打开首页右上角的“诊断”页，截图发给我。

请重点测试：
1. 示例曲目能否播放
2. SoundFont 是否能准备完成
3. 播放/暂停/进度条/轨道静音是否正常
4. 麦克风权限和跟随模式是否能进入
5. App 是否崩溃或卡住
```

## 发布前还缺什么

- Android release 签名，不再使用 debug 签名。
- 自动记录版本/提交 SHA 到 App 内，而不是手工看分支。
- 崩溃日志或最少可导出的诊断文本。
- iOS TestFlight。
- 隐私政策：麦克风只用于本地跟随检测，不上传音频。
