# 封闭试用版验收清单

> 适用范围：当前 iOS USB MIDI 封闭试用版。以 [`product/release_scope.md`](product/release_scope.md) 为准。
>
> 这不是 Android、麦克风跟随、通用 PDF OMR 或完整曲库的发布清单。若这些能力进入范围，必须先更新范围、能力矩阵和本清单。

本文用于发布或交付 iOS 试用版前的人工验收。自动化测试负责基础契约，本文重点覆盖资产、真实 iPhone、USB MIDI 电子琴、音色库交付、轨道静音和跟随模式。

## 1. 文档定位

适用于每次准备发布或交付试用版前的最后一轮检查。它要求留下可追溯的记录，而不是仅凭“我已经试过”判断通过。

本文不替代以下自动化质量门禁：

```bash
flutter analyze
flutter test
```

### 2.2 资产、范围与测试说明

- [ ] 本轮曲目仅使用已获准的 K.478 资产；其他内置 MIDI、PDF、页面图和 SF2 已从最终 Flutter asset manifest 与 IPA 中排除。仅隐藏首页入口不视为排除。

### 2.3 设备与测试素材

- [ ] 准备一台 iPhone 真机和一台支持 class-compliant USB MIDI 的电子琴

- [ ] 先在 Xcode 中启用无线调试，避免 Mac 调试线占用 iPhone 的 USB 接口
- [ ] USB MIDI 热插拔、跟随模式和长休止恢复必须使用真机复测
- [ ] 准备一份已获准分发的有效 MIDI 文件（默认使用 K.478）
- [ ] 准备一份无效或异常 MIDI 文件，用于导入失败路径
- [ ] 准备一份包含多轨道和明显长休止段的 MIDI 文件
- [ ] 准备一次首次安装或已清理 App 数据的状态，用于验证选定的音色库交付路径

## 5. 详细验收场景

### S0. 资产与范围核验

目的：确保演示、TestFlight 和构建产物没有把未授权资源或未实现能力带给测试者。

步骤：

- [ ] 对照构建产物、Flutter asset manifest、首页卡片、导入示例和 TestFlight 截图，列出所有随包、下载或展示的 MIDI、PDF、页面图、SF2、图标、字体和音频。
- [ ] 将每项与 [`evidence/asset_manifest.md`](evidence/asset_manifest.md) 对照；只有“已核验”的项可以随本轮分发。
- [ ] 保存本轮 K.478 的来源页、许可文本/存档、文件哈希和必要署名。
- [ ] 确认对外文字没有承诺 Android、麦克风跟随、通用 PDF OMR、AI 伴奏、完整曲库或离线音色库（若尚未验证）。
- [ ] 确认音色库策略已选定，且本轮构建中没有“随包但不加载”或“下载但未固定版本”的模糊状态；标为“禁止分发”的 SF2 不在最终 Flutter asset manifest 与 IPA 内。

通过标准：本轮全部资源有可复核证据，且文案与 [`product/capability_matrix.md`](product/capability_matrix.md) 一致。

### S1. 音色库交付路径

目的：验证选定的音色库策略在真实 iPhone 上可以播放，并在失败时不误导用户。

前置条件：已在资产台账中明确选择以下一种策略：随包离线加载，或固定版本、HTTPS 下载、完整性校验和明确失败体验。

步骤：

- [ ] 在首次安装/清理数据的 iPhone 上启动 App，记录实际音色库来源、版本和文件大小。
- [ ] 导入获准 MIDI 后确认非钢琴伴奏轨可以正常发声。
- [ ] 若使用下载：验证 URL 为固定版本、下载后进行了预期哈希/大小校验；断网或校验失败时有可理解的提示和重试路径。
- [ ] 若使用随包：在离线状态完成首次播放，并确认实际加载的正是登记文件。
- [ ] 在停止、seek、重新进入播放器后确认没有卡音或错误音色。

通过标准：真实 iPhone 上的实际交付路径与台账相符，并能在正常和失败条件下准确表达状态。

当前默认的“下载并缓存”实现尚未证明固定版本与完整性校验，不能仅凭能够下载就判定 S1 通过。

### S2. 导入 MIDI

目的：确认用户能从文件系统导入标准 MIDI 文件，并能看到曲目与轨道信息。

前置条件：准备一份获准的有效 MIDI 文件和一份异常 MIDI 文件。

步骤：

- [ ] 点击首页「导入乐谱文件」
- [ ] 选择一份有效 MIDI 文件
- [ ] 导入完成后自动进入播放器页面
- [ ] 播放器标题应显示当前曲目名称
- [ ] 轨道列表应显示可控制轨道
- [ ] 返回首页后尝试导入异常 MIDI 文件
- [ ] 导入异常文件时应显示解析失败提示，而不是崩溃

通过标准：有效文件能进入播放器，无效文件有错误提示。

### S3. 播放 / 暂停 / seek

目的：确认基础播放控制可用，seek 后没有残留长音。

前置条件：已完成 S2，播放器页面已有有效 MIDI 曲目。

步骤：

- [ ] 点击播放，当前时间和进度条开始推进
- [ ] 点击暂停，播放停止推进且没有持续长音
- [ ] 再次播放能从暂停位置继续
- [ ] 拖动进度条进行 seek
- [ ] 使用快进 / 后退按钮进行 seek
- [ ] seek 后播放位置正确更新
- [ ] seek 前后的活动音符应被清理，不应出现卡音或残留长音

通过标准：播放控制稳定，seek 后声音状态正确。

### S4. 设置页调整默认速度

目的：确认设置页能保存默认速度，并影响当前曲目或新导入曲目的初始速度。

前置条件：已导入一首 MIDI，并确认播放器可正常播放。

步骤：

- [ ] 从首页或播放器页右上角进入「设置」
- [ ] 调整「默认速度」滑块
- [ ] 点击「应用到当前曲目」后，当前播放器速度应更新
- [ ] 返回播放器并播放，确认速度变化可感知
- [ ] 重新导入一首 MIDI，新曲目应使用设置中的默认速度
- [ ] 点击「恢复默认」后，默认速度回到推荐值

通过标准：设置值能被保存、应用，并影响新导入曲目的初始速度。

### S5. USB MIDI 发现 / 热插拔

目的：确认电子琴直接连接 iPhone 后，App 能准确展示连接状态。

前置条件：电子琴已开机，准备好 USB 线或转接器。

步骤：

- [ ] 未连接电子琴时，播放器显示「USB MIDI · 未检测到设备」
- [ ] 将电子琴直接连接到 iPhone
- [ ] 页面应显示电子琴的 CoreMIDI 设备名
- [ ] 弹奏按键后 App 不崩溃，电子琴仍由自身扬声器发声
- [ ] 拔出 USB 后，页面恢复未连接状态
- [ ] 重新插入后无需重启 App 即可再次显示设备名

通过标准：连接、拔出和重连状态均正确，App 无需重启。

### S6. 跟随模式打开 / 关闭

目的：确认 USB MIDI 跟随生命周期完整，并且 App 不重复播放钢琴声部。

前置条件：已连接电子琴、导入分轨明确的 MIDI，并确认钢琴轨和伴奏轨没有共享会互相干扰的 channel/note。

步骤：

- [ ] 在轨道列表选择全部钢琴轨（通常包含右手与左手）
- [ ] 打开「跟随模式」开关，App 不应请求麦克风权限
- [ ] 所选钢琴轨全部自动静音，其余伴奏开始播放
- [ ] 弹奏电子琴，伴奏速度可被跟随逻辑调整
- [ ] 关闭跟随模式，播放速度恢复为 1.0x
- [ ] 钢琴轨恢复为开启跟随前的静音状态
- [ ] 多次打开 / 关闭不应崩溃或遗留静音状态

通过标准：跟随可重复进入和退出，钢琴轨不重复发声，用户原始轨道状态可恢复。

### S7. 长休止等待恢复

目的：确认跟随模式遇到长休止时能暂停等待，并在下一次有效起拍后恢复。

前置条件：使用 iPhone 和 USB MIDI 电子琴，导入包含明显长休止的 MIDI 曲目，并选择包含休止后旋律的全部电子琴轨。

步骤：

- [ ] 打开跟随模式并开始播放 / 演奏
- [ ] 当谱面进入长休止区间时，状态应进入等待起拍
- [ ] 伴奏应暂停或停止推进，不应在休止后自动抢跑
- [ ] 休止期间弹错音不应导致明显误恢复
- [ ] 演奏下一个正确起拍音后，状态应恢复实时跟随
- [ ] 伴奏应继续播放并根据演奏速度调整
- [ ] 关闭跟随模式后，等待状态应被清理

通过标准：长休止期间等待用户输入，下一次有效 onset 后恢复播放。

### S8. 试用说明与反馈闭环

目的：让测试者知道如何完成目标任务、哪些情况不在承诺范围，以及如何报告问题。

步骤：

- [ ] TestFlight 说明明确仅支持 iOS、class-compliant USB MIDI 电子琴与当前获准曲目。
- [ ] 说明电子琴自身发声、App 仅播放其余伴奏轨，且 USB 热插拔必须在真机验证。
- [ ] 列出已知限制：精确 MIDI 匹配不保证错音/跳段/复调，PDF OMR 不在本次试用范围。
- [ ] 提供反馈入口，并要求反馈包含 App 版本、iPhone/iOS、电子琴型号、连接方式、曲目与复现步骤；不要默认收集演奏音频。
- [ ] 明确出现资产/授权、音色库、崩溃或跟随严重失配问题时的暂停分发与回滚负责人。

通过标准：测试目标、限制、反馈和暂停条件对测试者可见且可执行。

## 6. 发布判定

- [ ] 自动化质量门禁全绿
- [ ] S0-S8 全部通过；S0（资产）、S1（音色库）、S5-S8（真机输入、跟随与试用说明）不可豁免，任一失败均阻止本轮分发
- [ ] iPhone 真机上至少完成一次 USB MIDI 热插拔、跟随模式和长休止恢复验收
- [ ] 资产台账、音色库记录、测试说明和验收记录已附到本次构建/commit
- [ ] 已定义严重问题（资产权利、音色不可用、崩溃、明显误跟随）出现时的暂停测试和回滚方式

满足以上条件后，才可以进入受控的小范围 TestFlight 试用；这不等于公开 App Store 发布就绪。
