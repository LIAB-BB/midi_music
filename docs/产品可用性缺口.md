# 产品可用性缺口

本文记录从“能跑的技术原型”走向“可以给真实用户测试的 App”还缺什么。它不是长期战略规划，优先关注近期可交付、可验证的产品能力。

## 当前已经具备

- 可以导入本地 MIDI 文件并播放。
- 可以使用内置 MIDI 示例曲目，不依赖用户自己找文件。
- 自动下载并缓存 SoundFont。
- 支持播放、暂停、停止、seek、变速。
- 支持按轨道静音、音量和主旋律选择。
- 有麦克风跟随模式基础能力。
- 有轻量诊断页，可查看音色、麦克风权限、当前曲目、版本和隐私提示。
- 有 `flutter analyze`、`flutter test` 和 GitHub Actions 质量门禁。
- UI 已拆出展示数据层、共享控件和施工说明，后续人工改视觉更容易。

## 近期必须补齐

1. **真实设备验收**
   - Android 真机：SoundFont 下载、播放、文件选择、示例曲目、后台/锁屏边界。
   - iOS 真机：麦克风权限、音频会话、外放/耳机、文件选择。
   - 需要记录设备型号、系统版本、结果和失败日志。

2. **错误恢复**
   - SoundFont 下载失败时给用户明确重试路径。
   - MIDI 解析失败时区分“文件损坏 / 格式不支持 / 权限问题”。
   - 播放引擎异常要能恢复到可再次播放的状态。

3. **首屏体验**
   - 首页需要解释“导入 MIDI”和“示例曲目”的差异。
   - 用户首次打开时应能在 30 秒内听到声音。
   - SoundFont 下载期间要避免用户误以为 App 卡住。

4. **跟随模式可用性**
   - 主旋律选择需要更明确的提示和推荐。
   - 麦克风权限被拒后应引导去系统设置。
   - 需要真实演奏测试，不只依赖单元测试。

5. **发布准备**
   - Android release 签名和版本号策略。
   - iOS Bundle ID、签名、TestFlight 配置。
   - 隐私说明：麦克风用途、是否上传音频、是否采集数据。

## 中期能力缺口

- 曲目库：从“导入 MIDI”升级到“可浏览曲目”。
- 乐谱显示：MusicXML / PDF / OSMD 方案还未落地。
- 更高质量音频：当前还是 SoundFont MIDI，距离商业级伴奏有明显差距。
- 跟随算法评估：缺少真实录音和人工标注数据集。
- 设置页：已有轻量诊断页；仍缺缓存清理、日志导出和更完整的设备信息。
- 崩溃/日志采集：测试版需要能拿到用户失败现场。

## 下一步推荐顺序

1. 完成内置示例曲目的首页体验和测试。
2. 整理真机测试 checklist，并打一个 Android debug APK 给第一批测试者。
3. 根据诊断页截图和真机反馈补错误恢复、缓存清理和日志导出。
4. 做一轮真实设备反馈后，再继续投入大规模 UI 重做或跟随算法升级。
