# 真机测试清单

目标：确认当前 App 是否已经适合给第一批真实用户试用。测试重点不是“功能看起来存在”，而是普通测试者能否在 30 秒内听到声音、遇到问题时能反馈有效信息。

## 测试前准备

- 使用最新测试分支：`codex/ui-redesign-handoff`
- Android 测试包优先使用 debug APK。
- iOS 测试需要真机签名或 TestFlight，当前尚未完成正式分发配置。
- 测试者反馈时至少提供：
  - 手机型号
  - 系统版本
  - App 版本
  - 诊断页截图或“复制诊断信息”文本
  - 复现步骤
  - 是否使用耳机/蓝牙音箱

## 必测路径

### 1. 首次启动

- [ ] App 可以打开，不闪退。
- [ ] 首页显示“导入 MIDI 乐谱”。
- [ ] 首页显示“示例曲目”。
- [ ] 右上角可以打开“诊断”页。
- [ ] 诊断页能显示音色、音色缓存、麦克风权限、当前曲目和构建信息。
- [ ] 诊断页“复制诊断信息”按钮可用。
- [ ] 诊断页“清理缓存”按钮会弹出确认，不会误触直接删除。

通过标准：首次打开后，测试者知道可以点示例曲目开始。

### 2. SoundFont 音色准备

- [ ] 诊断页音色状态可以显示检查/下载/就绪/失败。
- [ ] 下载失败时，诊断页或首页有重试入口。
- [ ] 疑似缓存损坏时，可以在诊断页清理缓存后重新准备音色。
- [ ] 下载完成后，播放按钮可用。
- [ ] 断网首次启动时不会闪退。

通过标准：网络正常时能完成音色准备；网络异常时能给出可截图反馈。

### 3. 示例曲目播放

- [ ] 点击 Beethoven 示例曲目可以进入播放器。
- [ ] 播放、暂停、停止可用。
- [ ] 进度条 seek 可用。
- [ ] 快进/回退/归零可用。
- [ ] 当前曲目显示正确。
- [ ] 回到首页后可以继续当前曲目。

通过标准：不导入外部文件也能完整听到声音并操作播放。

### 4. 本地 MIDI 导入

- [ ] 点击“导入 MIDI 乐谱”能打开文件选择器。
- [ ] 选择 `.mid` 文件后进入播放器。
- [ ] 损坏文件或非 MIDI 文件不会导致 App 崩溃。
- [ ] 解析失败能显示错误弹窗。

通过标准：用户自己的 MIDI 可以播放；错误文件可恢复。

### 5. 轨道控制

- [ ] 轨道列表显示轨道数量。
- [ ] 静音单个轨道有效。
- [ ] 调整轨道音量有效。
- [ ] 设为主旋律按钮有效。
- [ ] 多轨道共享 channel 的文件静音时不会误伤其他轨道。

通过标准：轨道控制能用于练习伴奏分层。

### 6. 跟随模式

- [ ] 未选择主旋律时打开跟随，会提示先选择主旋律。
- [ ] 首次开启跟随会请求麦克风权限。
- [ ] 拒绝权限后不会崩溃。
- [ ] 授权后诊断页显示麦克风已授权。
- [ ] 选择主旋律后可进入跟随模式。
- [ ] 长休止、seek 后跟随状态不会明显错乱。

通过标准：跟随模式至少能进入、退出、拒绝权限可恢复；真实跟随效果另做专项评估。

### 7. 稳定性

- [ ] 连续播放/暂停 10 次不崩溃。
- [ ] 连续切换 3 首示例曲目不崩溃。
- [ ] 播放时切到后台再回来不崩溃。
- [ ] 锁屏/解锁后不会卡死。
- [ ] 横竖屏或字体放大时文字不严重重叠。

通过标准：基础练习场景不需要重启 App。

## 当前已知限制

- Android release 仍未配置正式签名；第一批测试建议使用 debug APK。
- iOS 还没有 TestFlight 分发配置。
- 当前音色是 SoundFont MIDI，不代表最终商业级伴奏质量。
- 跟随模式需要真实乐器和真机麦克风验证，单元测试只能证明状态机边界。
