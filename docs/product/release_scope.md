# 当前试用版范围（iOS USB MIDI）

> 状态：当前权威范围。更新日期：2026-08-20。
>
> 这是一个**封闭试用候选方案**，不是公开商用版本承诺，也尚未满足 TestFlight 分发门槛。任何未列出的功能均不应在 App、截图、TestFlight 说明或销售材料中暗示为可用。

## 1. 用户任务

一名拥有 iPhone 和 class-compliant USB MIDI 电子琴的练习者，在练习一首已授权、已分轨的钢琴主导室内乐或协奏曲时：

1. 将电子琴直接连接到 iPhone；
2. 使用候选中固定的钢琴轨 4、5（左右手）；它们不进入 App 音频链路；
3. 启动跟随；
4. 由电子琴自身发出钢琴声，App 播放其余伴奏声部并随演奏速度调整；
5. 在长休止后等待下一次正确起拍，再继续伴奏。

首个垂直切片仅以莫扎特 K.478 钢琴四重奏为准。仓库仍保留通用曲库、MusicXML、PDF OMR 与麦克风跟随代码，供未来独立范围恢复；它们不构成本轮首页、导航路径、TestFlight 文案或验收承诺。

## 3. 明确不承诺

- 用麦克风识别任意乐器、错音、跳段、复调或专业 rubato。
- 通用 PDF 识谱、手写谱识别、总谱识别，或 PDF 与演奏进度自动同步。
- Android MIDI、跨设备 MIDI 兼容性、蓝牙 MIDI、云同步、教师管理或订阅。
- 管弦乐级预渲染音频、stem 混音、实时动态层、卷积混响或 AI 生成伴奏。
- 未进入资产台账且未完成分发授权核验的曲目、音色、PDF 或封面。

PDF OMR 未来若要从开发协议恢复为产品能力，至少应同时具备：认证和结果访问控制、速率/并发限制、文件类型/页数/大小校验、TLS、恶意文件防护、数据保留与删除流程、真实谱面的端到端准确率证据。没有这些证据，它始终不进入试用范围。

## 4. 试用版必须回答的产品问题

这些是待验证假设，不是已证明结论：

| 假设 | 需要的证据 | 不通过时的处理 |
| --- | --- | --- |
| USB MIDI 的设置成本低于麦克风跟随带来的不确定性 | 记录首次连接、启动跟随所需帮助与失败原因 | 收窄设备名单或改进引导，不能扩展曲库掩盖问题。 |
| 钢琴主导室内乐练习者愿意用此流程 | 访谈和封闭试用中的完整练习任务记录 | 重新定位为 MIDI 文件练习工具，或停止投入。 |
| 精确 MIDI 匹配足以支持第一首曲目 | 真实演奏中记录失配、误恢复、长休止失败和主观可接受度 | 不宣传“智能伴奏”；先改善数据与算法。 |
| 伴奏音色满足试用目的 | 在同一设备、同一曲目下收集明确反馈 | 先解决音色交付和音源质量，再做内容扩张。 |

## 5. 发布前不可豁免门槛

1. **资产**：所有随包或下载的 MIDI、PDF、页面图、SoundFont 和品牌资源均有可复核来源、许可、署名义务与分发渠道记录。K.478 的本轮核验记录见 [`../evidence/k478_asset_evidence.md`](../evidence/k478_asset_evidence.md)。
2. **音色库**：本轮已选择随包离线加载两个单预设 SF2。放行前必须完成官方输入比对、成品哈希与授权通知复核、签名 IPA 内容检查和 iPhone 真机发声；不得把根开发 host 的浮动 TimGM6mb 下载路径带入候选。
3. **真机**：完成 `docs/release_checklist.md` 的目标设备记录，尤其 USB 热插拔、跟随、长休止、停止后恢复。
4. **范围**：App 和 TestFlight 元数据只描述本页列出的能力。Apple 要求 Beta 应符合 App Review Guidelines，且外部测试需要提供测试信息和审核。见 [Apple TestFlight](https://developer.apple.com/testflight/) 与 [App Review Guidelines](https://developer.apple.com/app-store/review/guidelines/)。
5. **保留能力的二进制边界**：旧的 OMR、麦克风和文件导入代码继续留在仓库根开发 host；发布候选使用 `apps/testflight_ios` 独立 Flutter host 与 `packages/k478_practice` 共享功能包，避免生成旧插件的注册和 Pods。最终签名 Archive 仍需复核插件注册、Info.plist、Privacy Report 与实际资产，不能只依据源码结构。
6. **反馈闭环**：已定义反馈入口、已知问题、回滚方式和下一次是否扩大测试的 Go/No-Go 判断。

## 6. 下一次决策

在扩大曲目、开始麦克风跟随或建设后端前，先完成一首曲目的封闭试用。届时根据证据选择一个方向：

- 继续做“USB MIDI 电子琴室内乐练习助手”；
- 为麦克风跟随建立单独的研究基线；
- 终止或重新定位产品。
