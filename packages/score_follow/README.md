# score_follow

可容错的实时乐谱跟随内核，纯 Dart，无 Flutter / 平台依赖。已接入
`packages/k478_practice` 的 `K478AdaptiveFollowSession`，候选页面默认使用；
尚未完成 iPhone + USB 电子琴真机验收。

现有 K.478 候选的跟随算法是“严格逐音匹配”：只允许当前期待的那一个 onset，
错一个音就停在原地，连续三次错音才把播放器 seek 回期待位置；跳过音符后
期待位置仍在后面，用户只能停止重开。它没有 look-ahead，也没有真正的
位置估计，速度只在两次正确起拍之间做一次 EMA。

本包把问题改成在线多假设对齐：

- 每个假设维护“下一期待 onset + 锚点时间映射 + 速度 + 置信度”；
- 每次 Note On 在 `[next - 1, next + lookahead]` 窗口内找音高匹配，
  允许漏音、跳音、错音、和弦尾音与长休止后重锚；
- 速度由相邻正确匹配的谱面/墙钟时间比估计并做 EMA；
- 错误音只消耗 miss，不改变位置；漏音时向前开低置信度分支，分支在
  主假设存活期间置信度封顶，避免并行重复段落抢位置；
- 重新捕获用“墙钟推进 × 当前速度”预测谱面时间，而不是只按 onset 序号
  就近猜；
- 初始锁谱限制在曲首窗口内，避免开头反复音型被锁到几十个 onset 之后；
- 输出位置、速度、置信度和时间误差，由上层决定启动、调速或纠偏。

## 用法

```dart
final follower = AdaptiveScoreFollower(score: score);
final update = follower.onNoteOn(60, performanceSeconds);
if (update.matched && update.confidence >= 0.5) {
  // 以 update.scoreTime 对齐伴奏，以 update.speed 调整速度
}
```

`performanceSeconds` 必须来自单调时钟（`Stopwatch`），不要用
`DateTime.now()` 的墙钟差。

## 验证

```bash
dart pub get
dart analyze
dart test
dart run tool/benchmark.dart
```

`tool/benchmark.dart` 用仓库内 K.478 钢琴声部（1922 个 onset、3116 个
音符、约 8 分钟）构造模拟演奏，对比旧式严格匹配与本内核：

| 场景 | 算法 | 精确位置 | 误差 ≤1 onset | 速度 MAE / 中位 | 锁定所需音数 | 最大位置跳变 | 跳页恢复 |
|---|---|---:|---:|---:|---:|---:|---:|
| 干净 rubato + 和弦拆分 | v1 严格 | 98.8% | 100.0% | 0.027 / 0.018 | 1 | 1 | — |
|  | v2 多假设 | 99.1% | 99.9% | 0.023 / 0.018 | 3 | 2 | — |
| 3% 错音 / 1.5% 漏音 / 2% 装饰音 | v1 严格 | 1.5% | 1.5% | 0.016 / 0.015 | 1 | 1 | — |
|  | v2 多假设 | 97.7% | 99.8% | 0.024 / 0.018 | 3 | 10 | — |
| 中段跳页 +10 | v1 严格 | 4.0% | 4.1% | 0.018 / 0.017 | 1 | 1 | 未恢复 |
|  | v2 多假设 | 97.3% | 99.3% | 0.023 / 0.017 | 3 | 19 | 12 音 |

速度指标只统计“已锁定且位置完全正确”的音符；v1 在失误/跳页场景中样本
极少，所以它的速度数字没有代表性。模拟是确定性的，可用固定 seed 复跑。

## 边界

- 只消费 MIDI Note On（或等价起拍），不做音频 onset 检测。
- 默认从曲首附近开始；任意段落起奏需要上层传入 `preferredStartIndex`，
  或后续增加全局序列对齐。
- 不处理完整反复（da capo）与同时多声部交叉；并行重复段落仍可能造成
  重新捕获到错误位置。
- 没有接播放器传输层：相位误差如何转成调速/seek、以及音频中断、拔线、
  后台恢复，仍由上层会话负责。K.478 的 `K478AdaptiveFollowSession`
  目前只做了启动锁、重捕获 seek、0.8 s 大漂移保护和拔线终止。
